# 会社選択の待ち時間短縮とラフター入力画面の整理

確認日：2026-10-29。公開版：1.4.4+7。
基点：main `113a5c67b85aeb72336437a13a89932e68807779`。

## 会社名が出るまでの処理

旧処理は、会社→点検者→会社を直列に取得し、すべて終わるまで選択画面全体を待たせていた。
点検者取得では、所属未設定の旧データを書き換える処理も表示前に待っていた。

今回の変更：

- 会社と点検者を並行取得し、会社が届いた時点で選択肢を表示する。点検者の読込は待たない。
- 会社の重複取得を除去。初回は会社・点検者それぞれ1回の取得とする。
- 現場選択中に両方を先読みし、次画面で同じ取得要求を共有する。
- アプリ内で取得済みの一覧は再訪時にすぐ表示する。1分以内は再利用し、期限後は表示を残してバックグラウンド更新する。
- 同じ取得中の要求をまとめる。登録・削除後は無効化し、古い通信結果が新しいキャッシュを上書きしない。
- 右上「会社・点検者を更新」から即時更新できる。別端末から追加した名前をすぐ反映したい場合にも使用できる。
- 旧点検者の所属は選択画面用の表示データ上で補完し、この画面を開くための書込みは行わない。既存ID・保存済み文書は保持する。
- 人数は点検者の未読込中は「読込中」、取得失敗時は「—」とし、未取得を0名と誤表示しない。
- 通信失敗は再読込できる。更新が遅れても、この画面で直前に登録した会社・点検者を消さない。

キャッシュは会社・点検者マスタのメモリ内スナップショットだけで、点検記録や写真は保持しない。
ブラウザ自体を再読み込みした最初の取得は通信が必要。端末・回線によって通信時間は変動する。

## ラフター入力画面

25t・50t共通の入力画面から「ラフターの点検区分・確認上の注意」の展開欄を削除した。
14項目、★区分、良・不良、写真・メモ、未入力時の扱い、保存方式は変更しない。
記録詳細、月次Excelの凡例・法令表示、根拠資料は維持する。

## 検証結果

- 全49テスト成功（既存37件＋追加12件）。
- 点検者の応答を保留しても、会社の応答だけで会社名が表示される。
- 会社・点検者の両応答を保留しても、キャッシュがあれば会社名を表示できる。
- 同時読込は1回に集約、期限切れ・強制更新・失敗後再試行、無効化前の応答が上書きしないことを確認。
- 旧所属の表示補完を行っても既存文書が不変であることを確認。
- 会社／点検者の登録・削除でキャッシュを無効化し、遅い更新が新しい登録を消さないことを確認。
- 会社・点検者の取得失敗を未登録／0名と混同しないことを確認。
- 25t・50tとも注意欄がなく、初期値0/14であることを確認。既存の点検保存・帳票・登録・戻る操作のテストも成功。
