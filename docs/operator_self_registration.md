# 点検フロー内の会社・点検者登録

確認日：2026-10-29。公開版：1.4.3+6。
調査基点：main `fd595a2d911966e4fb61c555a77aa8aa01b148e5`。

## 変更後の使い方

1. 現場を選び、点検者選択画面へ進む。
2. 所属会社を選ぶ。点検者が0名の会社も表示する。
3. 会社がなければ「会社名を追加」から入力し、「登録して選択」を押す。
4. 点検者がなければ「点検者名を追加」から名前を入力し、「登録して選択」を押す。
5. 登録に成功すると会社・点検者を自動選択する。「次へ」で従来の機械選択・点検へ進む。

点検者ロールで利用でき、管理者の事前登録を必要としない。
登録した会社と点検者は、次回から既存の一覧及びマスタ管理画面でも取得できる。
検索中の名前は点検者追加の入力欄へ引き継ぐ。

## 原因と変更ファイル

会社の取得後に「その会社の点検者が存在するか」で会社一覧を絞っていたため、
点検者未登録の会社を選べず、新規オペが点検を始められなかった。

|ファイル|変更内容|
|---|---|
|`lib/screens/inspector_selection_screen.dart`|会社の絞り込みを除去し、全有効会社を表示。会社・点検者の追加ボタンと登録成功後の自動選択を追加。|
|`lib/widgets/master_name_registration_dialog.dart`|会社名・所属会社を示す点検者名の入力。空白入力検証、保存中の二重押し防止、失敗時の入力保持と再試行、キャンセル。|
|`lib/services/firestore_service.dart`|点検フロー用の会社登録・会社に紐づく点検者登録。既存ID再利用、トランザクションによるこの追加経路の重複防止。|
|`pubspec.yaml` / `pubspec.lock`|公開版1.4.3+6。既存cryptoの同じバージョンを実行時依存へ移動。|
|`test/operator_registration_test.dart`|登録・重複・所属・既存保全、点検者ロールの入力・保存までの11テスト。|

## Firestore保存

- 会社は既存の `companies`、点検者は既存の `inspectors` を使用する。
- 会社：`name`、`isActive: true`、サーバー時刻の `createdAt`。
- 点検者：上記に加え、選択した会社の `companyId`、会社文書から確認した `companyName`。
- 入力前後の空白を除く。有効な同名会社、同じ会社の同名点検者は既存IDを再利用し、既存文書を変更しない。
- 新規文書は名前、又は会社IDと名前から決まる固定IDを使用し、トランザクション内で存在を確認する。再操作・同時登録でもこの追加経路で重複文書を作らない。
- 別会社の同姓同名は区別する。存在しない／無効な会社への点検者登録は中止する。
- 空入力・キャンセルでは書き込まない。読込や登録に失敗したまま登録成功・選択済みとして扱わない。

既存会社・点検者のID、点検記録、機械マスタ、点検項目、帳票の保存形式は変更しない。
データ移行やマスタ一括投入、Firestoreルールの変更は不要で、実行していない。
登録は利用者が「登録して選択」を押した時だけ行う。

## 検証

- 全37テスト成功：既存26件＋追加11件。
- 会社なし・点検者なしから点検者ロールで会社／点検者を登録し、機械選択→14項目の点検保存→再訪時の一覧表示を確認。
- 点検者0名の会社も表示し、無効な会社を表示しない。
- 新規会社の同時登録、同じ会社の同名点検者の同時登録で文書が1件。別会社の同姓同名は2件。
- 既存の会社・点検者のID・フィールドを保持して再利用。
- 空白、キャンセル、存在しない／無効な会社への登録を拒否。
- 会社／点検者の登録失敗時に入力を保持し、再試行成功後のみ選択。
- 保存中の登録ボタンを無効化し、1回だけ呼び出す。
- 390×844の画面・キーボード相当の下端300pxでもフォームが崩れず登録できる。
- 静的解析：エラー0、新規指摘0。既存314件（変更前と同じ）。
- JavaScript Web releaseビルド成功（本番と同じ `/Inspect-Pro/` ベースパス）。
