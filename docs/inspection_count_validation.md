# 点検データ総件数の1,000件上限の修正

確認日：2026-10-20。ラフター追加と同じPR #6で本番公開する。

## 原因と変更

`FirestoreService.getInspections()` が `inspections.limit(1000)` の結果だけを返していたため、管理画面の総件数・今月・今日・現場等のフィルタ・一覧が取得済み1,000件だけを対象としていた。

- `lib/services/firestore_service.dart`：文書ID順に500件ずつ `startAfterDocument` で末尾まで取得する。500件は取得単位であり総件数上限ではない。日付フィールドがない旧記録も取得し、従来の日付降順に並べる。途中の読込エラーは部分件数として返さず呼出元へ伝える。
- `lib/screens/admin_screen.dart`：全ページの取得完了後に件数を表示する。読込中は「読込中」、失敗は「取得失敗」と再読み込みボタンを表示し、0件や部分件数を確定総数として表示しない。既存のフィルタ中はフィルタ対象件数を表示する方式を維持する。
- `test/inspection_count_test.dart`：境界件数、全ページを使う集計・フィルタと失敗後の再試行を検証する。画面にはテスト用DB注入を追加する。

既存の記録・ID・結果の書換えやデータ移行はない。Firestoreの追加複合インデックスも不要。

## 検証

- 0・500・1,000・1,001・1,505件の全件取得、重複なし・欠落なし。
- 1,000件より後の最新日付の記録と、日付フィールドなしの旧記録を含める。
- 実管理画面ウィジェットで総件数1,001、現場Aで501、フィルタ解除後1,001を確認。
- 取得失敗を「取得失敗」と表示し、再読み込み後に1,001を表示。
- 再読み込みの成功メッセージも取得完了後に1,001件と表示し、失敗時に成功表示しない。
- ラフターの保存・詳細・Web月次Excel生成・既存機種帳票の8件も含め、計16件成功。
- 最終静的解析：エラー0、新規指摘0、既存317件（warning13・info304）。変更前mainは323件、ラフター追加時点は318件で、今回未使用importを1件削除した。
- Webリリースビルド成功。既存のWasm事前確認警告は継続するが、対象のJavaScript Web出力は成功。
- 既存 `test/widget_test.dart` のVM非対応 `dart:html` による失敗は変更前にも再現済み。今回の16件はすべて成功。

```sh
flutter test --no-pub test/inspection_count_test.dart test/rough_terrain_crane_test.dart
flutter analyze --no-pub
flutter build web --release --no-pub --base-href=/Inspect-Pro/
```

本番 `inspect-pro-22e0a` / `(default)` / `inspections` を既存Firebase CLI認証で読取専用確認した。
2026-10-20 03:01:44 UTC時点で集約件数 **1,338件**。
文書ID順・500件単位でフィールドを取得せず照合した結果は500・500・338件、ユニークID数1,338で一致した。
個々の点検内容や写真は取得せず、検証用点検記録の追加・変更・削除はしていない。
利用者の追加・削除により件数は変化する。
